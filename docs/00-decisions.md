# Kage: decision record from discovery

Date: 2026-10-08. Source: structured Q&A with the project owner. Every row here
is a settled decision unless marked "open". Agents must not re-litigate these
without an ADR that supersedes them (see `docs/adr/`).

## Mission

Kage is a self-hosted API service that fetches web pages for the owner's
personal projects while being indistinguishable from a real human user at
every layer software can control: network egress, TCP/TLS/HTTP fingerprints,
browser fingerprint, JavaScript environment, and input behavior. It must run
excellently on any site it is pointed at; there is no fixed target list.

## Decisions

| # | Area | Decision |
|---|------|----------|
| D1 | Browser | A real browser is core, not a fallback. It runs in an anti-detect browser sidecar (TypeScript on Node, Playwright-compatible). Rust talks to it over an internal HTTP/JSON API. |
| D2 | Engines | Two engines behind one contract: patched Chromium (patchright, real Chrome channel, CDP leaks hidden) for Chrome personas and Camoufox (Firefox fork with C++-level fingerprint injection) for Firefox personas. Persona mix is Chrome-weighted to follow real market share. |
| D3 | Display | Headful under a virtual display (Xvfb or Camoufox's built-in virtual display) in Linux containers. Never new-headless in production. |
| D4 | Fetch path | Per-domain policy decides `http` (wreq) or `browser`. Unknown or protected domains default to browser. Automatic escalation http → browser on block. Cookies earned by the browser may be reused by wreq only with a matching fingerprint profile. |
| D5 | Proxies | Webshare Static Residential (ISP) proxies: a fixed list of IPs managed through the Webshare list and replacement API. Plan bought 2026-10-09: **Shared** exclusivity (the IPs are used by other Webshare customers too; Private and Dedicated were priced out), **250 GB/month** bandwidth, 20 IPs, **No Refreshes** (never a scheduled rotation), **50 manual replacements per month**, **High IP Reputation** add-on. Kage's automatic budget `proxies.replacements_per_month` stays small (code default 5; set it to 10 in the deployed `kage.yaml`) because an automatic replacement also retires the persona; the remaining replacements are for the owner's manual `kage proxy replace` when reputation or usage-type alerts fire. Countries: FR 4, DE 4, GB 4, AT 4, IT 4. Consequences: reputation lookups, per-domain cooldowns learned from outcomes and the replacement budget are the defence against shared-IP history; Kage must track bandwidth against the 250 GB cap and warn at 80 % (scheduled for M7 with the scheduler, alert routing in M12). |
| D6 | Personas | One long-lived persona per proxy IP (1:1). A persona owns a generated real-device fingerprint, engine, OS, locale, timezone and geolocation coherent with the IP, a persistent browser profile (cookies, storage, history), and a matching wreq emulation profile for the http path. |
| D7 | Fingerprints | Generated from a real-device fingerprint database (Apify fingerprint-suite for Chromium, Camoufox's generator for Firefox), pinned for the persona's lifetime, re-applied deterministically on every session. |
| D8 | Behavior | Full human emulation: Bezier mouse paths with overshoot, scroll with reading pauses, dwell from a human-like distribution, per-key typing cadence, idle periods. |
| D9 | Pacing | Human-like defaults per persona and per domain, with per-domain policy overrides. The caller may fully control pacing per request unless the domain policy locks it. |
| D10 | Blocks | Detect and classify by vendor and type. Let the browser pass silent challenges natively. No external CAPTCHA solvers, no manual solving. Retry with another persona up to N, cool the blocked persona down for that domain, per-domain circuit breaker, then report the classified block. |
| D11 | API | REST/JSON with OpenAPI 3.1 generated from the Rust types. Sync `POST /v1/fetch`, async jobs for batches, navigation flows and crawls. |
| D12 | Output | Everything is available and the caller selects via an `include` list: rendered DOM HTML, raw network body, headers and status, extracted text/markdown/metadata/links, captured XHR/fetch responses, screenshots, PDFs. |
| D13 | Interactions v1 | Page loads, scripted navigation flows (click, type, scroll, paginate, wait), screenshots and PDFs. No logins with owner accounts in v1. |
| D14 | Crawling | Frontier-based crawler is in v1: seeds, allow/deny, depth, page caps, sitemaps, dedupe, politeness via pacing. |
| D15 | robots.txt | Superseded by D46 (M11, 2026-10-13): a site's `robots.txt` is asked for only where the domain policy says `report` or `enforce` (default `ignore`), because a reader never asks for it and the request marks the address that does; where it is asked for, the verdict is on every result and enforced fully under `enforce`. |
| D16 | API auth | Per-consumer API keys with scopes and rate limits, stored hashed. |
| D17 | Direct mode | Never. If no usable proxy exists the request fails. The host IP never touches a target. |
| D18 | Replacement | A burned IP is replaced automatically through the Webshare API after sustained failure and backoff, bounded by a monthly replacement budget. Its persona is retired and a new one is generated. |
| D19 | Health | Reachability, latency, leak check, country match; fingerprint self-tests against detection test sites; IP reputation lookup on a slow timer; Webshare account sync via API. |
| D20 | Storage | PostgreSQL via sqlx with in-repo migrations. No ORM, no Redis. |
| D21 | Observability | Structured JSON logs (tracing), Prometheus metrics, OpenTelemetry traces. Dashboards and alerting are optional compose profiles. |
| D22 | QA gates | Every PR: rustfmt, clippy with warnings denied, unit and integration tests, sidecar lint/typecheck/tests, cargo-deny, cargo-audit, npm audit, secret scanning, SBOM, image scan, coverage threshold. Mutation testing reported on core crates. Live fingerprint regression suite runs nightly and before releases, not per PR. |
| D23 | Layout | Monorepo: Cargo workspace under `crates/`, Node pnpm workspace under `sidecar/`, `deploy/`, `docs/`, `policies/`. |
| D24 | Runtime | Linux server or VPS with Docker Compose. Development on Windows through WSL2 or a devcontainer. |
| D25 | Process | One milestone per agent session, one PR per milestone through the CI gates, ADRs for architecture decisions, `CLAUDE.md` with house rules. |
| D26 | License | Public repository, dual MIT / Apache-2.0, with a responsible-use section in the README. |
| D27 | Go project | `CarPriceScanner` is reference only. Nothing from it is binding. |
| D28 | AGPL dependency | ADR 0008 accepted with option B then C: M5 overrides `ua-parser-js` to the MIT 1.x line under the engine parity suite; if behavior differs, the Firefox image is not published and is built locally by operators. |
| D29 | Camoufox pin | M5 moves the Camoufox browser build to `v152.0.4-beta.30`, the only build `camoufox-js` 0.12.1 accepts with `playwright-core` 1.62.1, as the fingerprint-critical bump inside the M5 PR. |
| D30 | Merging | Until the repository was pushed (2026-10-17, `origin/main` at `adb8ba3`), milestone branches were fast-forwarded into local `main` by the owner and deleted. Since then the PR workflow of D25 is in force for every change, the planning documents included: a branch, a pull request, `ci-ok` green, a rebase merge that keeps the commits; the merged branch is deleted on GitHub. |
| D31 | Webshare auto-replace | `auto_replace_invalid_proxies` stays **on** in the Webshare account (owner decision 2026-10-09): Webshare replaces only a proxy its own checks find dead, which Kage would have replaced anyway after its backoff and `replace_after`. The other three `auto_replace_*` settings stay off. Kage's cope path (sync sees the swap, reads the reason from the replaced list, retires the persona, adopts the new IP) is the handling; the standing alert for this one flag is downgraded to an informational event (follow-up F16). |
| D32 | Camoufox build | Since 2026-10-19 (ADR 0011, which supersedes ADR 0010) the pinned Camoufox is `v156.0.1-beta.39`, by URL and checksum with its `omni.ja` by a second checksum, with no backport: the build grants no user activation to a page read by itself, and the engine refuses any other archive. The 152 build with the backport (ADR 0010) had four tells no stock Firefox has (a `chrome://juggler` worker a page could construct, unpartitioned cross-site storage, a popup without activation, fifteen extra `set…` globals); 156 removes them. The launch plan speaks the persona's language at startup (`intl.locale.requested` from a per-country table, through `CAMOU_PREFS`), never applies `navigator.doNotTrack` or `navigator.globalPrivacyControl`, sends no key the build declares removed, turns WebGPU on for Windows claims and Apple-GPU macOS claims, and keeps the memory cache and compression dictionaries at stock; `media.autoplay.default = 1` stays as a guard. Canvas pixels are the host's for every Firefox persona, as for Chromium (security review T1; the field campaign measures how rare that hash is, and the answer if needed is a real GPU, never noise). A persona moves to the engine's major at its next open (`POST /v1/personas/upgrade`, contract 1.4.0), keeping its sessions and cookies; a profile cannot go back to the older major, so the engine keeps a copy of it for `personas.upgrade_backup_days` (7). camoufox-js 0.12.1 and playwright-core 1.62.1 stay; a later major is a routine fingerprint-critical pull request by the audit script and the parity suite, with a live self-test on the owner's word. |
| D33 | Page reads | Every page read on chromium goes over the engine's own debugger session in an isolated, marked world without the gesture flag; the driver is used for launch, navigation, load-state and URL waits, network events and `human: false` steps only (spec §10.2, M5.1). The coherence probe fails hard when user activation exists without an activating input event. |
| D34 | Persona identity tables | A persona's screen class, locale and language list come from versioned tables in `kage_core::persona` (`tables_version` stored on the row, so a later table never moves an existing persona): screens are physical panel sizes only, drawn by weight from the persona seed and asked of the sidecar by exact bounds; languages are the stock list the persona's browser ships for its country's main language, with the locale tag carrying the country (keyboard, formats); multi-language countries have region overrides; an unknown country falls back to `en-US, en` with a health event. The engine mix is a seeded deficit-weighted draw, country first then pool, so every four-proxy country holds both engines. |
| D35 | Warm-up gates real work | Warm-up is on by default in production and off in tests and under `just dev`: a new persona reads a seeded subset of its country's reference and public-service pages (Wikipedia, OpenStreetMap, public broadcaster, weather service) with human behaviour during its daytime, and real work waits for `warmed_at` (3 finished visits or 12 h). A blocked warm-up site is skipped, never retried or escalated. |
| D36 | Scheduled self-tests and the probe host | Scheduled per-persona self-tests use only the operator's own echo and probe pages (`selftest.http.echo_url`, `selftest.browser.pages`), never a third party on a timer. With the shipped configuration none is scheduled, so a persona cooled for `geo_changed` or `selftest_failed` waits for an operator's `kage persona selftest`. The compose stack ships the echo and the probe site behind the `echo` profile; enabling them for proxy exits needs a DNS name and a certificate on the deployment host (runbook `fingerprint-echo.md`). Owner decision pending on whether to host them (open item O5). |
| D37 | Visits and days | A persona works a domain in visits of a few bursts and then leaves for a long break; the scheduler adds visitors only up to `domain_concurrency`; each persona has its own seeded waking hours and `active_hours: prefer` is the default; samplers are seeded per persona and starts are spaced so twenty personas never act in lockstep (spec §11, M7). The pacing gap counts from the start of the previous page and is a floor under the behaviour engine's time on the page. |
| D38 | Escalation and blocks | Under `auto`, a block a browser can cure is retried once by the same persona in its browser and the verdict comes from that attempt; a refusal or a browser block cools the persona (cooldown × confidence, 5 min floor, seeded jitter), ends its visit, closes its context, and another persona on another network retries after a seeded pause. The breaker is half-open with a doubling pause; warm-up visits count toward it, self-tests never (spec §3.2, §8.3, M7). |
| D39 | Forwarder and bandwidth | Every persona's browser and http client use one forwarder inside the kage process as their proxy, with a per-persona credential derived from the master key; the forwarder adds the provider's credentials upstream, relays `CONNECT` and absolute-form requests only, refuses any target the SSRF guard refuses and any persona that may not send, and counts both directions to the byte. The 250 GB budget is judged per subscription term on the larger of Kage's count and the provider's own; a warning at 80 %, a hard stop at 100 % by default (health probes and an operator's own self-test excepted). No fingerprint override switch exists in the binary; the http end-to-end with real personas waits for the first verified major (F30). |
| D40 | What the API lets through and gives out | A caller may shorten a browser page (scroll depth as given, dwell as a seeded median) only inside floors the domain policy owns (`min_dwell` 2 s, `behavior_locked`, a 15 s floor on the browser timeout); the pointer always wanders; a bare load is never reachable. Nothing is guessed or silently downgraded: a script's request kind needs its page as `Referer` and `render: http`; a method, body or caller header under a browser render is refused; unknown script headers are refused rather than placed. A non-admin key sees a per-key persona handle, engine, claimed OS and country, never a proxy, an address, a seed or a fingerprint; `Set-Cookie` values are redacted by default. A session never moves: conflicting hints are refused and only `POST /v1/sessions` opens one. The forwarding headers join the denylist (F34). The Python-2.0 licence of the test client's build-time `argparse` is allowed; nothing of that tree ships. |
| D41 | Jobs and visitors | A batch reads a site as one visitor by default: the first persona that gets through stays the visitor and the batch never wakes a sleeper; another persona takes over only when the visitor is blocked, capped, retired or its proxy unusable. A caller may ask for `visitors` up to the pacing's `domain_concurrency` (3 under `human`), refused beyond it, never clamped; the runbook and the OpenAPI say what it costs (measured in M9: 50 pages in about an hour on one address, 300 pages a day; 10 min on 3 to 5 addresses dealt out freely). No session by default; an optional job-level `session_id` pins every item under a fetch's session rules. An item that cannot be attempted now is deferred, not failed, and a job whose every remaining item waits is `paused` until the time the scheduler named, for at most `jobs.max_age` (7 d); only an item nobody can ever take fails. A synchronous fetch that outlasts the wall time is a one-item job under the request's own id and is taken up again after a restart with its earlier attempts in the record. A job is accepted whole or refused whole (spec §16.6, M9). |
| D42 | Flows | A flow is one browser attempt of one persona under one grant, starting with a `goto`, every `goto` through the SSRF guard at acceptance and every capture through the chain check after. Kage always asks the sidecar to pace it (contract 1.2.0: a dwell with a wandering pointer after every step that loads a document, thinking time between steps drawn from the flow's seed, the median from the request inside D40's floors and never below `min_dwell`). A step by the driver instead of the persona's hands (`human: false`) is refused with `driver_input_denied` unless the domain policy says `driver_input: true`, off by default, because a page can tell the two apart. A wall inside a flow is a blocked attempt (cool, close, breaker) and another persona runs the flow again from step one inside the retry budget; a step that fails without a wall is not retried and the flow is `partial` with the steps after it `not_run`; a flow in a session is never retried. `goBack` waits for commit and the sidecar looks at the address itself (F21). |
| D43 | Webhooks | A job's events go only to origins the operator listed (`webhooks.allowed_origins`, none by default; another origin is refused at submission with `webhook_origin_not_allowed`), because otherwise a key with the jobs scope could make the host's own address post a signed request at any public site. A listed origin that sits on the operator's own network goes into `webhooks.private_origins` as well, which lets it resolve to a private or loopback address; link-local, metadata and multicast addresses are refused for everyone and `kage config check` refuses a private origin that is not also allowed. The sender is plain wreq from the host's own address with an honest `User-Agent`, never through a proxy, resolving the name itself and connecting only to addresses it checked, following no redirect, checking again on every attempt. Events are thin (`{id, type, created_at, job}`), signed per attempt as `X-Kage-Signature: sha256=HMAC-SHA-256(<timestamp>.<body>)` under a secret sealed at rest and never returned; one attempt plus five retries at 30 s, 2 min, 8 min, 32 min, 2 h 8 min moved up to a fifth by the event's seed, `Retry-After` honoured up to an hour, `410` ends them, one in flight per receiver, an overtaken `job.progress` dropped, every attempt logged and pending ones surviving a restart. The forwarding-header family (`X-Forwarded-*`, `Forwarded`, `X-Real-IP`, `True-Client-IP`, `X-Client-IP`, `CF-Connecting-IP`, `X-Originating-IP`, `X-Cluster-Client-IP`, `Fastly-Client-IP`) is on the caller-header denylist (F34). |
| D44 | The patience of a page and the rest between two | No constant ends a visit. `timeout_ms` (floor 15 s) bounds reaching the page only; how long a persona goes on scrolling is a patience drawn by Kage per attempt from the attempt's seed (`browser.patience`: shifted log-normal, floor 6 s, median 38 s, p95 110 s, drawn again above 240 s, scaled by the persona's own pace), sent to the sidecar as `behavior.patience_ms` (contract 1.3.0) for every browser navigation, a warm-up page included; the scrolling ends at the depth asked or when the patience is spent, the dwell follows, and the result says the patience drawn, the depth reached and what ended the scrolling. The scheduler's wall bound on an attempt is derived from the time to reach the page, the patience, the dwell and a margin. No caller field bounds a visit; a caller who needs the bottom of a tall page uses a flow's `scroll` step. Between leaving a page and asking for the next one of the same sitting a persona rests for `rest_ms` of its pacing profile (`human`: floor 700 ms, median 2.2 s, p95 7 s, from the persona's seeded sampler; `fast`: none), applied by the planner on top of the start-to-start gap; the hand's travel before a click comes on top (spec §11, §13, M10). |
| D45 | A crawl reads like a reader | The next page of a crawl is (1) an unread text link of the page that is open, (2) an unread text link of a page one to three entries back in the tab, nearest first, (3) an unread menu link of the open page or within three backs, (4) a typed address, seeds first, then sitemap entries, then links whose page is out of reach; text links before furniture links, in document order. A link is clicked by the persona's hand on the page that is open, after keyboard `back`s when it is one to three entries back, and the result says how the page was reached; on the http path the page that holds the link is the `Referer`. Depth is the least number of links from a seed; `max_pages` counts pages asked of the site; no `order: breadth` exists. One visitor per site, the site being the registrable domain under the Public Suffix List, `visitors` up to `domain_concurrency`, refused beyond; `personas` of spec §13 became `visitors`, explicit persona ids are not offered, `defaults` is a batch's. `use_sitemaps` is off by default because a reader never asks for `/sitemap.xml`; when on, one persona that is not the crawl's visitor on that site asks once, through the scheduler like any page, and never reads that site (a Firefox persona preferred, since a gzipped sitemap is a download that only Camoufox hands over); sitemap entries are seeds at depth 0. Only links the browser renders are followed (`capture.links` with `visible` and `furniture`), hidden ones are counted as `skipped.hidden`; on the http path the markup's own hiding is honoured. Every address passes the SSRF guard before it is asked for. Dedupe: by normalized address (trailing slash kept, `www.` not folded, `http` and `https` two keys, 36 tracking parameters removed, redirects deduplicated by where they end) and by the text a reader sees without the site's furniture (SHA-256 for an exact copy, 64-bit SimHash at 6 bits or fewer for a near one, none under 24 words); a duplicate is stored and flagged, an exact duplicate's links are not followed. Files are not pages (`crawl.skipped_extensions`). A crawl is a batch whose list grows: the scheduler's visits, breaks and nights are its only caps (spec §13, M10). |
| D46 | robots.txt and the scout | A reader never asks for `/robots.txt`, so whether a site's file is asked for at all is its policy's: `robots: ignore` (the shipped default: nobody asks, every result says `fetched: false, allowed: true`), `report` (ask, report, fetch either way) or `enforce` (ask, never fetch what is disallowed, keep to `Crawl-delay` as a floor under each persona's gap on the host, jittered, no cap but 366 days). Who asks is the site's one scout: a persona that asks for the robots.txt of the site's origins and for its sitemaps and never reads a page of the site, remembered in `site_scouts`, chosen in order (the one that asked before; a ready persona the policy keeps from reading anyway; a ready persona that never read the site while the readers needed stay; nobody), a Firefox first among equals; it asks once, typed, through the scheduler like any page, as Kage's own request. One answer per origin for `robots.ttl` (24 h, jittered, refreshed on demand); a `4xx` is no file, a server error, timeout or block is unreachable for `robots.error_ttl` (1 h) and means disallowed under `enforce` (`robots_denied`, `robots_unavailable`, a job's pages paused; `robots_no_scout` when nobody can ask). Under `report` nothing waits and the scout follows the fetch; under `enforce` the first fetch of an origin waits for the verdict. The verdict is Kage's own parser and matcher by Google's rules (the `robotstxt` crate is the test oracle only, since it panics on input a site controls), the group of `*` and before it any group naming a token of `robots.agents` (`kage`). A request may ask for more care than the policy and never for less; `report`/`ignore` under an enforcing policy and `enforce` under an ignoring one are refused, never silently unenforced. A blocked scout cools and counts on the breaker like any persona (spec §14, M11). |
| D47 | The response cache | Opt-in per request (`cache_ttl_s`) or per site (the policy's `cache.ttl`), per API key unless the policy's `cache.shared` says the site shows everybody the same; `cache.max_ttl` (24 h, never beyond retention) bounds it and a longer ask is refused (`cache_ttl_too_long`), `0` means never. A hit is no visit and no page of the daily budget: answered before the scheduler, also while the site is paused or the pool sleeps, counted against the key's requests per minute; it shows the stored result under the new request's id with `cached: true`, `cached_at`, `attempts: []`, the verdict stored with it, and the persona handle only to the key that filled it. The key is everything that changes what a result holds (normalized URL, method, body, request kind, caller headers, `render` as asked, the include set, `wait`, `behavior`, screenshot, PDF and XHR options, `extract` options, `max_body_bytes`, the persona hints as asked) and nothing that changes only when or how politely it is fetched; different include sets miss. Stored only for `ok` or `challenge_passed` with a `2xx`, never a block, a failure, a refused redirect or a page whose extraction was thin; both the writer's and the reader's age bound hold. A crawl fills the cache and never reads it (a half-warm cache turns a reader's order into typed addresses); a flow never reads it; a request in a session neither reads nor writes it. Hits are rows of the hitting key pointing at the same content-addressed blobs, so purge and retention take nothing from another key (spec §15, M11). |
| D48 | Extraction | `include: ["extract"]` is read from the document the visit captured at the end of the attempt that got the page, never by a second request, null for a failed or blocked attempt and for a response that is no HTML; one tree per page, the crawler's, so what a crawl sees and what extraction returns never disagree. The main content is Readability's scoring ported onto that tree with three rules of Kage's own (markup furniture is never content and a page without a candidate has none; bylines are metadata; siblings of the same shape are content and a figure between two parts belongs), the markdown from the same walk, `thin_content` under `extract.thin_words` (80) words with `word_count` beside it and no guess about why. The fixtures are written, never recorded from a real site, with held-out pages that are measured and never tuned on (spec §14, M11). |
| D49 | Release and supply chain | A release is an annotated tag signed with the owner's SSH release key, whose public half is the one line of `.github/allowed_signers`; `release.yaml` verifies the tag before it builds, builds and scans the images without a layer cache, pushes `kage` and `kage-browser-chromium` to GHCR by digest, signs them keylessly with the workflow's own OIDC identity (`release.yaml@refs/tags/<tag>`), attests SLSA provenance and a CycloneDX SBOM to each digest, and publishes the GitHub release with the SBOMs and digests attached; the Firefox image is built locally by operators (ADR 0008). `deploy/compose.yaml` records the released digests in its header and the commands that run them. Commits are not required to be signed. `domain_rpm` is a cap on starts as Kage dispatches them; a site may see a request or two more inside a sliding minute by the variance of typing and loading, and the load test asserts the cap on Kage's record (design A in every pull request, design B before a release). The YAML of `kage.yaml` and the policies is read by `serde-saphyr` behind a provider of Kage's own, with a repeated key an error, merge keys refused, a budget of depth 128, a million nodes and 16 MiB of scalars, and unquoted text that looks numeric refused where text is expected. A stop of the server waits up to `jobs.wind_down` (150 s) for the pages being read and writes any attempt it cuts as `interrupted`. The `zip` advisories of `utoipa-swagger-ui`'s build script are accepted exceptions until 2026-12-31 or `zip` 9 (F55) (M12). |
| D50 | Camouflage levels and egress (2.0) | Every request names a `level` 0 to 3 and a request without one is refused (`level_required`): 0 plain (an HTTP client with wreq's own TLS and a `kage/<version>` User-Agent unless the caller sets one, no persona, no cookie jar, no behaviour; egress per `egress.plain`, the host's address or the pool as plain proxies in turn), 1 http-emulated (the persona's verified http client and pacing; `level_unavailable` while no verified major exists, F30), 2 browser-fast (the persona's browser, a plain load with the policy's `min_dwell` and the persona's pacing, no scrolling, no wander, no patience), 3 human (1.0). A site's policy sets `min_level` (default 0; the detection pages 3) and a request below it is refused (`level_below_policy`), never raised. `egress.mode` is `proxies` (default) or `direct`: under `direct` the host's own connection carries the traffic and one persona stands for it (`egress.direct.personas` 1), with its identity from the host's observed geo or the declared `egress.direct.country`/`locale`, warmed, paced and self-tested like any persona, the forwarder still fronting everything with no upstream; there is no mixed mode, because a visitor that moves from a residential address to the host's has shown a site a bot. A result says the level applied; `persona` is null at level 0; sessions need a persona; jobs and crawls take `defaults.level`; flows are 2 or 3; metrics carry `level`. The phase ships as 2.0.0 because the required field breaks every 1.x request on purpose (ADR 0012, M14). The owner decided this on 2026-10-19, superseding the never-direct rule of `CLAUDE.md` and the universal floors of D40 for the levels below 3. |
| D51 | Providers, declared lists and health (2.0) | `ProxyProvider` is the plugin surface and gains `capabilities()`: replacement, the replaced log, account sync and stats are optional, shown as unsupported rather than failing; a provider is one module under `kage-proxy/src/provider/`, its configuration section, its pins in `docs/versions.md`, and a pass of the conformance suite against a mock of its API, with a step-by-step guide in `CONTRIBUTING.md`. A static (YAML) entry carries `country` and may carry `locale` and `city`; a persona is generated from the declared values as from an observed geo record, `locale` overriding the country's primary language; an entry without a country gets no persona and is usable at level 0 only, with a warning. Where a geo lookup is possible it verifies the claim: a mismatch on two lookups is `geo_mismatch`, `degraded` and an alert, the declared identity kept. `proxies.health.echo_url` names the reachability and leak echo; for a provider without an echo of its own its default is the public echo 1.0 already used for confirmation (`https://checkip.amazonaws.com/`), the owner's choice, with the runbook saying the echo's operator sees the pool on the probe's schedule and that the operator's own echo (O5) is the private alternative. Webshare's path is unchanged and `auto` prefers it when its key is set (ADR 0013, M15; widens D5). |

## Honest limits (from `bot-detection-landscape.md`)

Even a perfect browser cannot pass hardware-rooted device attestation (Private
Access Tokens, PACT, Play Integrity), and some vendors specifically probe the
automation transport (CDP, patched runtimes). The design therefore treats
"indistinguishable" as a measured property: a fingerprint and behavior test
suite runs continuously against public detection test pages and the service
reports its own detection score per persona and engine. Regressions in that
score block releases.
